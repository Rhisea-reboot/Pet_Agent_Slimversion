## 2. 缺口（按产品价值排序）

| 缺口 | 现状 | 影响 |
|---|---|---|
| 情感→动画闭环 | `emotion.rewrite` 产出 LLM 自由标签，动画资产仅 Happy / ill / PoorCondition 3 种 | 核心卖点"有情绪"落不到表现层，产品感停在"会说话的 GIF"（已按 2026-08-04 决策推迟） |
| 打扰控制 | 仅固定冷却 + 摘要指纹去重，无用户忙碌 / 播放中 / 专注模式 | 主动发话是桌宠灵魂，当前策略粗糙，长时间使用会被嫌弃 |
| 分层记忆 | 仅持久化 `conversation.history`，无限增长 | 无跨日用户建模（喜好 / 习惯），token 成本随时间线性上升 |
| LLM 客户端基础能力 | 无流式（SSE）、无重试 / 退避；**取消已补齐**（按 requestId abort、超时/失败单飞清理） | 弱网 / 服务抖动仍表现为"宠物不理人"，但不再永久挂起，失败有可见反馈 |
| 感知级去重 | 已落地本地差分门控（灰度缩略图 320×180、阈值 24、3% 像素）+ 60s 派发预算 + JPEG/1280 工作线程编码 | 视觉 API 调用从 3 秒一帧降到最快 60 秒一帧且仅在画面显著变化时发生（WIP 未提交） |
| 工程基建 | 无 CI、无 LICENSE、`tts_config.json` 含个人营销文本被跟踪 | 回归全靠本地，公开分发存在法律与隐私边界问题 |
| 产品化 | 无设置 UI、纯 JSON 配置；发行包 5-6 GB | 面向普通用户的冷启动成本极高 |

## 3. 可扩展方向（依托现有架构）

现有 DAG + `semantic.*` key 协议 + 异步桥是真正可生长的骨架，扩展成本低：

- **工具调用循环**：`llm.chat` 已预留 tools 参数位、设计了 `tool.executor` / `agent.think` 子图方案，是下一步能力升级主线（日历提醒、定时器、剪贴板）
- **记忆节点**：新增 `memory.save` / `memory.recall` 节点即可接入分层记忆，不改运行时
- **打扰控制**：感知侧已有处理器链（`PerceptionPipeline::AddProcessor`），加一个前台窗口检测处理器即可实现"忙碌判断"
- **情绪动画**：资产侧补 Sad/Angry + 标签→mood 映射 + 未知标签回退，改动面只在映射层
- **平台 / 入口**：`web.research` 状态机、视觉管道与 Qt 解耦良好，可移植到移动端或 Web 复用

## 4. 同类竞品水平对比

| 维度 | VPet（本项目） | 开源 VPet (C#) | Live2DViewerEX | AI 桌宠（露娜 / 元气类） |
|---|---|---|---|---|
| 动画与交互 | Qt 原生，A/B/C 状态机，中等 | 丰富（GIF 生态） | 顶级（Live2D 模型市场） | 中等 |
| AI 对话 | DAG 可编排 Agent | 弱 | 无 / 弱 | 云端大模型 |
| 屏幕感知 | **独有**（无竞品做） | 无 | 无 | 少数有 |
| 联网研究 | 有（本地 daemon + 预算控制） | 无 | 无 | 无 |
| 隐私 | **本地优先**（TTS/ASR 本地，截图不落盘） | — | — | 弱（数据在云端） |
| 安装 / 资源 | 5-6 GB（致命短板） | 几十 MB | 百 MB 级 | 百 MB 级 |
| 生态 / 社区 | 无 | 有 | 有市场 | 有 |

**结论**：技术架构（DAG Agent + 本地感知 + 本地 TTS）领先于几乎所有同类，差异化明确；但产品完成度、分发成本、生态是明显弱势——与 C# VPet 相比缺动画生态，与商业 AI 桌宠比缺记忆与情感表现力。定位是"极客向本地 AI 桌宠"，发行包 6 GB 无法与几十 MB 的竞品竞争。

## 5. 安全性

### 5.1 已做对的（走查确认）

- API key 全部 gitignore，Git 历史无泄露痕迹（恒为占位符）
- 截图仅存内存、隐私 opt-in 默认关闭；屏幕 / 语音敏感数据无落盘
- 子进程全部 QProcess 参数数组调用（`src/speech/voice_input_manager.cpp:288`、`src/tts_server_manager.cpp:141`），无 shell 注入面
- 联网仅访问本地 daemon（127.0.0.1），检索预算受限，外部结果按不可信数据处理
- URL / 超时 / 参数全面钳制（`src/llm/llm_client.cpp:24-34` 边界校验）
- TTS 失败日志不再打印服务端响应正文，避免用户台词回显进日志文件（本日修复）
- 同步 HTTP 调用（TTS 启动探测）已改异步，UI 线程不再被 waitForStarted 阻塞（本日修复）

### 5.2 剩余风险

1. **提示词注入**：屏幕内容（网页、广告）未经处理即进视觉摘要，可诱导主动话语输出任意内容——当前无工具执行危害有限，但接入 tool-calling 前必须先处理
2. **密钥存储**：api_key 明文存 `llm_config.json`（可改 DPAPI）；无 TLS 证书固定
3. **本地 daemon 无认证**：本机任意进程可调用 3210 端口
4. **供应链**：ASR 模型经 modelscope 联网下载（已改离线路径）；GPT-SoVITS vendored 更新不可控
5. 敏感上下文（截图、历史）明文发往云端 LLM，文档应明示隐私边界

## 6. 性能

### 6.1 瓶颈点

- **视觉链路成本**（本日已大幅缓解）：已改 JPEG 1280 + 本地差分门控（3% 像素差触发）+ 60s 最小派发间隔 + QtConcurrent 工作线程编码，全屏 PNG 上行与 UI 卡顿问题消除；剩余为调参无设置 UI、阈值固定
- **TTS 重负载**（本日部分缓解）：启动改异步 + 120s 总超时 + 健康检查单飞 + 崩溃自动重启（最多 3 次）；torch 推理链 1.5-3 GB 常驻内存与 CPU 慢速仍属固有
- **内存**：帧缓冲已默认关闭（enableBuffer=false），仅保留待编码单帧副本
- **会话历史无限增长** → 请求体 / token 成本递增，无窗口裁剪（已防失败轮次污染，但窗口策略未做）

### 6.2 建议

视觉链路降本已落地（差分触发 + 工作线程编码）；下一步建议：TTS 改为可选懒启动（说第一句话前再拉起），历史加窗口 / 摘要压缩策略。

## 7. 总结

- **优势**：架构范式领先（DAG Agent 同 LangGraph 代）、安全卫生 A 级、测试文档闭环良好、取消/看门狗/原子性等工程硬伤已闭合
- **最大缺口**：产品完成度（情感 / 打扰 / 记忆）+ 发行成本（6 GB）
- **最该先做**：提交本轮修复批次 → CI + 提示词注入隔离（接入 tool-calling 前）→ 打扰控制 → 记忆窗口
